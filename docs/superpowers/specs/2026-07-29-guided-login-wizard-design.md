# Task 3 中文首次登录向导设计

状态：已获确认

## 范围

本次只增强首次打开或账号未连接时的账户连接引导，不实现卡密库存、交付内容或其他配置页面。普通账号表格、扫码登录弹窗和已有页面入口保持兼容。

## 设计

- 在账号管理页顶部增加可关闭、可重新打开的向导卡片。
- 左侧使用 6 步进度：准备登录、扫码、等待稳定、需要人工验证/等待退避、连接成功、验证可用。
- 右侧只呈现当前状态对应的一项主要动作；等待状态明确写出“当前无需操作”。
- 前端读取 `GET /setup/status`，兼容单账号 `status` 与多账号 `accounts` 返回；操作通过 `POST /setup/action`，不改变既有 API。
- 服务端 `retry_at` 作为唯一倒计时截止时间。前端每秒计算显示，归零后立即刷新状态；状态刷新周期为 3 秒。
- 只有 `vnc_manual_action_available` 或 `manual_browser_session_status` 明确表示有活动浏览器时，才显示“接管验证”。没有活动浏览器时只显示重新打开验证/等待提示。
- 错误状态提供下一步建议，技术细节放入可折叠区域；主提示不暴露 WebSocket、Token 等技术词。
- 使用原生按钮、`aria-live` 状态区域、可见焦点和窄屏单列布局，复用现有 Bootstrap 与 CSS 变量。

## 状态行为

| `primary_action` / `technical_status` | 当前提示 | 主动作 |
| --- | --- | --- |
| 无账号或未连接 | 请打开闲鱼 App 扫码；不要重复扫码 | 打开扫码登录 |
| `qr_login_grace_wait` | 扫码已完成，正在稳定账号，当前无需操作 | 等待 |
| `password_login_backoff_wait` | 正在等待恢复机会，显示服务端剩余时间 | 等待 |
| `verification_pending_manual` | 自动验证没有完成，请按按钮人工验证 | 有活动浏览器时接管，否则重新打开验证页面 |
| `connected` / `finish` | 连接成功，继续验证可用 | 验证可用 |
| 其他错误 | 告诉用户保持浏览器打开并重新检查 | 重新检查 |
